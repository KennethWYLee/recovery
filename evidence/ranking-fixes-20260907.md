# 排序操作、公布與教師端狀態修正

2026-09-07 發布前驗證紀錄。使用者正在課堂同步測試，已授權修正、提交與部署。

## 依據與修改

- 查閱 PROJECT.md、學生排序元件、教師課堂與參與紀錄元件、課堂 API、資料庫流程及現有測試。正式課堂唯讀畫面顯示小組回答已收到，但個人排序僅收到一份；未據此宣稱學生曾送出的其他排序遺失。
- 依使用者明確修正，取消固定三位學生的公布門檻；以實際有效學生排序計算，至少一份，沿用教師排序要求。規則記錄於 PROJECT.md。
- 學生排序改為明顯的文字按鈕、待選回答優先、取消剛才選擇、上下調整及確認送出。保留原本排序算法與排除自己組的計算。
- 教師端學生參與紀錄原本不會定時更新；改為每六秒讀取，並明確區別小組回答與個人排序。
- 尚未公布的鎖定問題可由管理員重新開放排序；保留提交、分組快照及操作紀錄，拒絕舊版本與已公布問題的重開。
- 較多人數開放新問題的測試發生 500；將每人快照及每組回答的新增改為分開預備敘述、同一批交易，避免單一敘述累積過多參數。完整人數重測通過。
- 修改涉及 app 的排序、參與紀錄、問題控制元件與樣式，新增重開 API 與資料層函式，調整 classroom-live／classroom-live-security、測試腳本及既有檢查。quality-exceptions.json 僅下修因元件抽出而改善的基線。

## 驗證與限制

- 建置、型別、lint、程式品質檢查通過；單元測試 77/77、SQL 流程 17/17、建置產物檢查 4/4 通過。
- `npm run test:api-simulation`：316 個請求、0 個非預期失敗；新增一份與兩份排序公布、無排序及無教師排序拒絕、重新開放保留原排序、舊版本拒絕、已公布後拒絕重開及參與紀錄反映实际提交的測試。
- 所有寫入測試只在隔離的本機虛擬資料執行。取消讀取測試產生 Windows workerd 連線中止訊息，後續恢復與整體測試通過。
- 未清除、代填、代送或改寫正式課堂的學生回答與排序，未自動公布正式課堂。未另跑完整 mutation、coverage、依賴稽核或真人手機可用性驗證；不把可點選的實作視為已證明學生理解更好。
- 本檔為提交前紀錄；實際部署結果以 Sites 部署狀態與對話中的確認為準。
