# P1-P4 四位組員個人證據格式

文件版本：`1.0.0`  
目前狀態：`planned_template`  
適用方式：假設每組四人，每人各自填寫並接受逐人口頭查核或現場操作。團體文件、自動測試或 AI 產出不能自動證明個人能力。

## 1. 共同規則

- 每位組員選擇自己真正負責且能追溯的核心流程，不必四人寫同一份答案。
- GitHub 證據使用「有意義的起訖 commit 區間、實際差異、決策及驗證」，不使用 commit 數、程式行數或貢獻線圖換算能力。
- 合併 commit 可以作為里程碑，但必須指出自己實際決定與完成的內容。
- 隊友或 AI 的協助要照實寫；個人要說明最後判斷、驗證與責任界線。
- P4 情境由教師、委員或未參與該功能的人事前準備。受測組員不能先看到答案，且不一定要修改程式；資料、設定、權限或外部服務問題應採相稱處理。
- 不自行填分數。若證據不足，直接標示「尚未證明」，不要用推測補齊。

## 8. 委員快速核對

對每位組員分別確認：

1. P1 能從操作一路說到實際程式、資料與回應，也能正確預測變更影響。
2. P2 的成果有本人決策、產物、驗證及結果，不把團體成果全部列為個人貢獻。
3. P3 至少兩段實質版本區間能從 diff 看出問題、取捨、測試與持續推進，不使用數量替代內容。
4. P4 未事前看過答案，能先保護資料，再用證據縮小問題、採相稱處理，重跑原失敗與相關回歸。
5. 回答與 repository、issue、PR、Log、測試及受評 artifact 一致；不一致時以實際證據為準並追問原因。
